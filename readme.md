# Симулятор автоматизированной парковки (ИДЗ №2, многопоточная версия)

Каждый участник модели — автомобиль, диспетчер, генератор прибытий — работает в отдельном потоке (`pthread`). Потоки взаимодействуют через мьютекс и семафоры. Однопоточная версия первого задания описана в [report1.md](report1.md), многопоточная — в [report2.md](report2.md).

## Требования к окружению
Для успешной сборки и запуска приложения потребуются:
*   ОС: Linux (WSL)
*   Компилятор: `gcc` (C11, библиотека `pthread`)
*   Системы сборки: `cmake` и `make`

## Инструкция по сборке

Выполните следующие команды в корневой директории проекта:

```bash
# 1. Создаем директорию для сборки и переходим в нее
mkdir build
cd build

# 2. Генерируем файлы сборки
cmake ..

# 3. Компилируем проект
make
```
В результате в директории `build` появится исполняемый файл `parking_sim`.

## Запуск программы

Вы можете запустить симуляцию с параметрами по умолчанию или гибко настроить их через аргументы командной строки.

### Базовый запуск
```bash
./parking_sim
```

### Запуск с пользовательскими параметрами
Программа поддерживает настройку всех ключевых переменных через флаги командной строки.

**Пример теста (много машин, мало мест, долгая стоянка):**
```bash
./parking_sim -t 200 -q 5 -r 1 -l 1 -s 0 -p 15 -P 30 -c 20
```

**Доступные аргументы:**
*   **Длительность симуляции:**
    *   `-t `: Предельное число тактов симуляции (по умолчанию: 100). `-t 0` — без ограничения: симуляция идёт, пока не будут обработаны все автомобили, или до Ctrl+C.
    *   `-d `: Длительность одного такта в миллисекундах (по умолчанию: 800). Например, `-d 1` — почти мгновенный прогон.
*   **Воспроизводимость и стратегия:**
    *   `-R `: Начальное значение генератора случайных чисел (по умолчанию: текущее время). Seed выводится на экран и в лог. При одинаковом seed и параметрах повторяются все случайные величины (типы автомобилей, интервалы прибытия, время стоянки), но порядок событий в журнале может немного отличаться: он зависит от того, как ОС переключает потоки.
    *   `-g `: Стратегия, по которой диспетчер выбирает из очереди автомобиль на освободившееся место (среди машин подходящего типа):
        *   `fifo` (по умолчанию) — дольше всех ждущий;
        *   `lifo` — последний вставший в очередь;
        *   `random` — случайный;
        *   `short` — с самым коротким временем стоянки (место быстрее освободится для следующих).
*   **Журнал:**
    *   `-L `: Путь к файлу журнала (по умолчанию: `../parking_result.txt`).
*   **Инфраструктура парковки:**
    *   `-q `: Максимальная вместимость очереди (по умолчанию: 3).
    *   `-r `: Количество мест для *Обычных* авто (по умолчанию: 2).
    *   `-l `: Количество мест для *Крупногабаритных* авто (по умолчанию: 1).
    *   `-s `: Количество мест для *Специальных* авто (по умолчанию: 1).
*   **Генерация трафика (пул автомобилей):**
    *   `-c `: Количество генерируемых *Обычных* авто (по умолчанию: 15).
    *   `-C `: Количество генерируемых *Крупногабаритных* авто (по умолчанию: 12).
    *   `-S `: Количество генерируемых *Специальных* авто (по умолчанию: 10).
*   **Поведенческие таймеры:**
    *   `-a ` / `-b `: Мин. и макс. интервал между прибытиями машин в тактах (по умолчанию: 0 и 2; 0 — несколько машин приезжают одновременно).
    *   `-p ` / `-P `: Мин. и макс. продолжительность стоянки (по умолчанию: 7 и 10).
    *   `-w `: Максимальное время ожидания машины в очереди до ухода (по умолчанию: 8).

## Устройство программы

| Модуль | Назначение |
|---|---|
| `main.c` | Запуск: параметры, старт потоков, ожидание завершения, итоги |
| `threads.c` | Потоки: генератор, автомобили, диспетчер, отрисовщик, обработка сигналов |
| `parking.c` | Общее состояние парковки (места, очередь, статистика, мьютекс) |
| `queue.c` | Кольцевая очередь автомобилей |
| `strategy.c` | Стратегии выбора автомобиля из очереди |
| `params.c` | Значения по умолчанию, разбор и проверка аргументов |
| `sim_clock.c` | Такты в реальном времени, прерываемый сон, генератор случайных чисел |
| `logger.c` | Журнал событий |
| `ui.c` | Дашборд и итоговая статистика |

Заголовки модулей лежат в `include/`. Подробное описание потоков и синхронизации — в [report2.md](report2.md).

## Взаимодействие и интерфейс

В процессе работы программа выводит на экран динамический текстовый дашборд.
*   **Альтернативный буфер:** Интерфейс отрисовывается в альтернативном буфере терминала, поэтому после завершения работы история ваших команд не будет засорена.
*   **Безопасное прерывание (Ctrl+C):** Программа корректно обрабатывает сигналы `SIGINT` (Ctrl+C) и `SIGTERM` (`kill <pid>`). При прерывании автомобили в очереди получают отмену, припаркованные досрочно уезжают, все потоки завершаются, после чего программа сохраняет логи и выводит итоговую статистику.

## Условия завершения
1.  Все автомобили обработаны (обслужены, ушли из очереди или получили отказ).
2.  Истёк лимит времени `-t` (при `-t 0` лимита нет).
3.  Получен сигнал `SIGINT` (Ctrl+C) или `SIGTERM`.

Причина завершения выводится в итоговой статистике.

## Логирование и результаты

После завершения симуляции в корневой папке будет сформирован файл **`parking_result.txt`** (при запуске из `build/`; другой путь задаётся флагом `-L`).
В нем содержится:
1.  Хронология всех событий с номером такта: прибытие, постановка в очередь, назначение места, начало и окончание стоянки, освобождение места, уход из очереди, отказ.
2.  Итоговая статистика обслуженных и потерянных клиентов.

Для просмотра лога используйте утилиту `cat` или `less`:
```bash
cat parking_result.txt
```

## Тестирование

В папке `tests/`:
*   `cases.txt` — тестовые наборы параметров с ожидаемым исходом (обработка всех авто, лимит времени, ошибка в параметрах);
*   `check_log.awk` — проверка журнала: инварианты (место не занято двумя авто, авто не находится одновременно в очереди и на месте, очередь не переполнена), допустимый порядок событий для каждого авто и совпадение итоговой статистики с журналом;
*   `run_tests.sh` — прогоняет все наборы (такт 1 мс), а также проверяет завершение по `SIGINT` и `SIGTERM`.

```bash
# из корня проекта, после сборки в build/
tests/run_tests.sh
# или с указанием исполняемого файла
tests/run_tests.sh путь/к/parking_sim
```
Журналы прогонов сохраняются в `tests/logs/` (`01.txt`, `02.txt`, ... — по номеру теста).

Для поиска гонок данных и ошибок памяти проект можно собрать с санитайзером и прогнать те же тесты:
```bash
mkdir build-tsan && cd build-tsan
cmake -DSANITIZE=thread ..     # или -DSANITIZE=address
make
../tests/run_tests.sh ./parking_sim
```
