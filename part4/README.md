# Четвёртая часть: парковка по TCP

Четыре самостоятельные программы на C, рассчитанные на накопительные требования
выше 8 баллов. Предыдущие реализации остаются в `part2/` и `part3/`.
Подробности и **фактические границы проверки** — в [report4.md](../report4.md).

## Сборка

Из корня репозитория в Linux/WSL:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --target parking_tcp parking_tcp_checks -j 4
```

Бинарники находятся в `build/bin/part4/`. Нужны C11, libc и CMake;
все программы работают без Docker и без Python. Python 3.9+ нужен только тестам.
Новые цели не требуют POSIX MQ или общей памяти.

## Программы

```text
parking_server IP ПОРТ [флаги модели]
parking_car АДРЕС ПОРТ НОМЕР
parking_arrivals АДРЕС ПОРТ
parking_monitor АДРЕС ПОРТ [--plain]
```

У сервера сохранены флаги модели из третьей части: `-r/-l/-s`, `-c/-C/-S`,
`-q`, `-a/-b`, `-p/-P`, `-w`, `-g fifo|lifo|random|short`, `-t`, `-d`, `-R`, `-L`.
Путь журнала по умолчанию — `parking_result.txt` относительно cwd.
Для сетевого варианта ограничены суммы: до 4096 автомобилей, до 2048 мест,
вместимость очереди до 4096; превышение отклоняется.

`АДРЕС` — IPv4 либо имя хоста (например, имя сервиса Docker). Порт — 1..65535.
`0.0.0.0` у сервера означает прослушивание всех IPv4-интерфейсов;
клиенты подключаются к конкретному адресу сервера.

## Ручная демонстрация уровней

### 4–5: собственный вывод сервера и автомобилей

Терминал 1:

```bash
./build/bin/part4/parking_server 0.0.0.0 5050 -t 0 -d 100 -r 1 -l 0 -s 0 -c 3 -C 0 -S 0 -p 100 -P 100 -w 300 -R 7 -L parking_tcp_result.txt
```

В других терминалах:

```bash
./build/bin/part4/parking_car 127.0.0.1 5050 1
./build/bin/part4/parking_car 127.0.0.1 5050 2
./build/bin/part4/parking_car 127.0.0.1 5050 3
```

Сервер выводит принятые события модели, каждый автомобиль — только свои решения.
Общее табло отсутствует до запуска наблюдателя. Для автоматических прибытий
используйте `parking_arrivals 127.0.0.1 5050` вместо ручного запуска номеров.

### 6–7 и 8: отдельное табло и несколько наблюдателей

До запуска автомобилей или во время работы сервера откройте дополнительные терминалы:

```bash
./build/bin/part4/parking_monitor 127.0.0.1 5050
./build/bin/part4/parking_monitor 127.0.0.1 5050
```

Каждое табло получает полный актуальный снимок: места, номера автомобилей,
остаток стоянки, очередь, статистику и последние три события. Наблюдатели
не запускают часы модели. Ctrl+C закрывает только выбранного наблюдателя;
его можно запустить снова. В терминале используется альтернативный ANSI-буфер;
`--plain` или перенаправление stdout дают последовательность снимков без ANSI.

### Выше 8: восстановление рабочих клиентов

Во время очереди или стоянки нажмите Ctrl+C в терминале автомобиля, затем запустите
ту же команду с прежним номером. Сервер продолжает моделирование, время не сбрасывается.
Клиент получает текущий статус; если стоянка уже закончилась — конечный результат.
Команда ARRIVE отправляется только при начальном статусе «ожидание решения»;
восстановление очереди, стоянки или конечного результата её не повторяет.
Номер не учитывается как второе прибытие. Два одновременно активных клиента одного
номера отклоняются. После аварийного разрыва обнаружение старого соединения может
занять до 5 с; после него номер снова доступен.

Генератор тоже можно завершить и запустить повторно: он запрашивает планы у сервера,
пропускает завершённые и уже подключённые номера, восстанавливает отключённые и выпускает
оставшиеся. При штатном отключении генератор завершает и собирает только собственных
детей. Сервер и вручную запущенные автомобили продолжают работу. Одновременный ручной
запуск и запуск генератором одного и того же номера могут дать ожидаемый отказ дубликату.

Автоматического бесконечного переподключения нет: после ошибки связи клиент выходит,
пользователь повторяет команду. После завершения самого сервера восстановление его
памяти на диске не предусмотрено; новый сервер создаёт новую симуляцию.

### Завершение

Сервер заканчивает модель после обработки всех N автомобилей, по `-t` либо SIGINT/SIGTERM.
Без участников часы не идут; первый ARRIVE или подключение генератора запускает их.
Наблюдатели не расходуют лимит. При N=0 сервер завершается сразу.

При остановке очередь отменяется, стоянки прерываются, сохраняется статистика,
всем подключённым ролям отправляются финальное состояние и STOP. На подтверждения
отведено до 2 с. Клиенты подтверждают STOP и выходят; генератор подтверждает STOP
после сбора детей. Во время этой фазы новые TCP-подключения получают STOP,
новые прибытия уже не регистрируются.
При аварийном исчезновении сервера клиенты выходят с ошибкой; отсутствие входящих
сообщений ограничено 5 с. Штатное завершение, включая собственный Ctrl+C клиента,
даёт код 0; ошибки — 1.

## Скрипты

```bash
part4/scripts/demo.sh 5050 -d 100 -g short
PARKING_MONITOR=0 part4/scripts/demo.sh 5050 -d 100
```

Демонстрация сохраняет журнал сервера и вывод генератора в отдельной папке `/tmp`,
путь выводится при запуске. Обёртки `run_server.sh`, `run_car.sh`, `run_arrivals.sh`,
`run_monitor.sh` принимают те же аргументы, что бинарники. `PARKING_TCP_BIN` позволяет
выбрать каталог другой сборки. Для N=0 используйте непосредственно сервер.

## Проверка на разных компьютерах

На компьютере A запустите сервер с `0.0.0.0`. На компьютере B укажите IPv4 компьютера A:

```bash
./build/bin/part4/parking_car 192.168.1.10 5050 1
./build/bin/part4/parking_monitor 192.168.1.10 5050
```

Адрес приведён как пример — замените его реальным. Порт сервера должен быть доступен
между компьютерами; в WSL доступ зависит также от сетевого режима и настроек Windows.
Этот сценарий подготовлен, но в текущем окружении **ещё не выполнен**.

## Docker

Из корня репозитория:

```bash
docker compose -f part4/compose.yaml build server
docker compose -f part4/compose.yaml --profile observe up --scale monitor=3
```

Сервер, генератор и три наблюдателя работают в отдельных контейнерах. Сервер доступен
с хоста по `127.0.0.1:5050`; `PARKING_PORT=5051` меняет опубликованный порт.
Журнал сохраняется в `part4/logs/parking_result.txt` на хосте.

Во втором терминале можно отключить и вернуть генератор, затем остановить сервер:

```bash
docker compose -f part4/compose.yaml stop arrivals
docker compose -f part4/compose.yaml start arrivals
docker compose -f part4/compose.yaml stop server
docker compose -f part4/compose.yaml --profile observe down
```

Для возврата генератора сервер ещё должен работать: если все логические автомобили
уже обработаны, моделирование закончится естественным образом. Начальные интервалы
Compose оставляют время для демонстрации. Контейнеры одного компьютера не заменяют
проверку двух физических хостов.

Образ собран и проверен в Docker Desktop: сервер, три наблюдателя, отдельный автомобиль
и генератор работали с разными IP в одной Docker-сети. Успешно проверены отключение
и восстановление автомобиля, наблюдателя и генератора, завершение всех клиентов
по остановке сервера и инварианты журнала. Для повторения приёмки (порт 5050 должен быть свободен):

```bash
python3 part4/tests/check_docker.py --build
```

Скрипт создаёт отдельный Compose-проект с уникальным именем, переопределяет параметры
для длительной демонстрации и после проверки удаляет только свои контейнеры и сеть.
Он сохраняет команды, вывод и итоговый журнал в `/tmp`; временный override и уникальный
журнал сервера создаются в игнорируемом `part4/logs/`. Образ `parking-tcp:local`
остаётся доступным для последующих запусков.

## Тестирование

```bash
cmake --build build --target parking_tcp parking_tcp_checks -j 4
part4/tests/run_tests.sh --unit
part4/tests/run_tests.sh
```

`--unit` выполняет четыре C-проверки: транспорт с подменой send/recv без реальных сокетов,
предметную модель, обработчики сеансов и поведение клиента автомобиля.
Журналы проверяются AWK; также выполняются
28 проверок ошибок CLI. Полный запуск дополнительно выполняет 26 сетевых
тестовых метода с подслучаями, включая 35 наборов параметров из третьей части:
ручной запуск, генерацию, наблюдателей, восстановление, сигналы, аварии, повреждённые
сообщения, фрагментацию, ранний отъезд, медленного наблюдателя и параллельные серверы.
Также проверяются ANSI-табло через настоящий псевдотерминал, остановка во время
HELLO и десять повторов короткого лимита с ещё подключающимися детьми генератора.
Тесты сами выбирают свободные порты. Журналы сетевого прогона сохраняются в `/tmp`,
путь печатается при запуске; `PARKING_TEST_LOGS` меняет родительский каталог.
Для каждого метода и набора создаётся отдельный подкаталог, в том числе при ошибках.

Проверки через assert принудительно включены и в Release. Тестовые бинарники
собираются отдельной целью `parking_tcp_checks` и не входят в обычную сборку программ.

```bash
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug -DSANITIZE=address,undefined
cmake --build build-asan --target parking_tcp parking_tcp_checks -j 4
ASAN_OPTIONS=detect_leaks=0:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 PARKING_TCP_BIN="$PWD/build-asan/bin/part4" part4/tests/run_tests.sh
```

Сборки Debug и Release и модульные проверки в обеих конфигурациях выполнены успешно.
Полный TCP-прогон: **26 методов без ошибок** на обычной сборке и **26 без ошибок**
под ASan/UBSan. Внутри набора — 35 сценариев параметров и дополнительные подслучаи;
их не следует повторно прибавлять к числу методов. После обнаружения гонки остановки
исправлен порядок STOP/ACK и добавлены воспроизводящие проверки.
LSan не запускался по прежнему ограничению проекта.
